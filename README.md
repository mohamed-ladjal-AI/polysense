# PolySense Analytics — prototype

Demo web app for the soft-sensor presented in the master thesis
*Conception d'un soft-sensor basé sur l'intelligence artificielle pour la
supervision en temps réel d'une ligne d'extrusion PVC* (KraussMaffei
KMD 90-36).

## What is real here

- The **machine branding** (KMD 90-36, PVC rigide) matches the thesis.
- The **XGBoost model** in `model_artifacts/xgb_model.joblib` is the actual
  model trained by `anis/trainer.py` (F1 défaut = 0.85 on the synthetic
  test set). It is served by a real FastAPI backend (`api.py`).
- The **`LivePrediction` component** on the dashboard fetches the real
  `/predict` endpoint every 3 seconds and shows the model's actual output.

## What is mocked

- The **process data** (live chart, gauges, alerts, etc.) is *synthetic* —
  the backend reads the last row of the simulated dataset that the thesis
  uses. There is no real connection to an extruder.
- The **5 "static" metrics** at the top of the dashboard (Quality / Degradation
  / Yellowing / Stability / HCl) are still hard-coded client-side. They
  will be replaced by the `LivePrediction` panel in a future iteration.
- The **sidebar items** `AI Predictions`, `Alerts & Recommendations`,
  `History & Reports`, `Settings` are placeholder links (Coming soon).

## Running locally

You need two services running.

### 1. Backend (FastAPI)

```powershell
# from the polysense/ folder
$env:POLYSENSE_ANIS_DIR = "C:\Users\ASUS\Desktop\yasser memoir\anis"
python -m uvicorn api:app --port 8000
```

Then check `http://127.0.0.1:8000/docs` (Swagger UI) and
`http://127.0.0.1:8000/predict` (raw JSON).

If `model_artifacts/` is empty, regenerate from the thesis side:

```powershell
$env:POLYSENSE_ARTIFACTS_DIR = "C:\Users\ASUS\Documents\js\polysense\model_artifacts"
python "C:\Users\ASUS\Desktop\yasser memoir\anis\save_model.py"
```

### 2. Frontend (Vite)

```powershell
# from the polysense/ folder
npm install   # if first time
npm run dev
```

Open the printed URL (usually `http://127.0.0.1:5173`). The
`LivePrediction` card on the dashboard pulls from the backend.

To point the frontend at a different backend URL, set
`VITE_POLYSENSE_API=http://...` in a `.env` file at the project root.

## Endpoints

- `GET /`         — service banner
- `GET /healthz`  — `{"status": "ok", "model_loaded": true}`
- `GET /model-info` — model metadata (F1, precision, recall, n_features…)
- `GET /predict`  — one-shot prediction from the last row of the synthetic dataset
- `POST /predict` — same, but you can override individual process variables

The `POST /predict` body is a JSON with any subset of the 14 features
(extra fields are ignored, missing ones default to the last simulated row).
